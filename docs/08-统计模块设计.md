## 1. 统计系统总体架构与数据流向

为避免大屏统计分析的高频 `COUNT/SUM/GROUP BY` 慢查询直接冲击 OLTP 核心业务表（`borrow_records`、`book_copies`），统计模块采用**多级分治架构**：

```mermaid
graph TD
    DB[(PostgreSQL 17 数据库)] -->|1. 实时轻量索引聚合| RealtimeService[实时指标计算服务]
    DB -->|2. 每日凌晨定时跑批汇总| DailyCronJob[定时报表任务 (01:00 AM)]
    DailyCronJob --> DailyTable[(日/月度统计快照)]
    RealtimeService --> RedisStats[(Redis 统计缓存 Key TTL: 10分钟)]
    DailyTable --> RedisStats
    RedisStats --> AdminAPI[统计分析对外 API]
    AdminAPI --> VisualUI[管理端可视化大屏 / 学生端热门发现]
```

## 2. 统计指标体系与数学口径定义

### 2.1 馆藏与流通总体大屏（Overview Metrics）

| 指标名称 | 统计口径与业务定义 | SQL 计算逻辑与公式表达 | 性能与更新策略 |
| :--- | :--- | :--- | :--- |
| **馆藏书目种类数** | 馆内收录的不同 ISBN 抽象书目总数 | `SELECT COUNT(id) FROM books;` | Redis 缓存 30 分钟 |
| **物理副本总存量** | 全校流通中的物理单册总数（剔除已报废） | `SELECT COUNT(id) FROM book_copies WHERE status != 'SCRAPPED';` | 变化低频，缓存 1 小时 |
| **当前在借总册数** | 当前被读者借出在外的物理图书单册总数 | `SELECT COUNT(id) FROM book_copies WHERE status = 'BORROWED';` | 缓存 5 分钟 |
| **在架可借总册数** | 当前处于架上，读者到馆即借的可用册数 | `SELECT COUNT(id) FROM book_copies WHERE status = 'AVAILABLE';` | 缓存 5 分钟 |
| **在排队预约数** | 处于排队等待中的有效书目预约单总量 | `SELECT COUNT(id) FROM reservations WHERE status = 'WAITING';` | 缓存 5 分钟 |
| **当前在借逾期数** | 处于借出中但已超过应还截止时间的册数 | `SELECT COUNT(id) FROM borrow_records WHERE status = 'OVERDUE' OR (status = 'BORROWING' AND due_at < CURRENT_TIMESTAMP);` | 每日定时 + 缓存 10 分钟 |
| **有效读者总人数** | 注册且状态正常（未被注销）的学生与教工数 | `SELECT COUNT(id) FROM users WHERE status = 'ACTIVE';` | 缓存 1 小时 |

### 2.2 借阅流通趋势分析（Borrowing & Return Trends）

* **日趋势（近 30 天）**：以天为窗口，统计每日新产生借书借阅量与每日验收入库归还量。
* **月趋势（近 12 个月）**：以自然月为窗口，呈现学期周期波动（开学借书高峰、期末归还高峰）。

---

### 2.3 热门借阅图书榜单（Popular Books TOP 10）

* **计算口径**：统计最近 90 天内被借阅频次最多的前 10 本书目（按 `book_id` 聚类）。
```sql
SELECT 
    b.id AS book_id,
    b.isbn,
    b.title,
    b.cover_url,
    b.available_copies,
    COUNT(r.id) AS borrow_times
FROM borrow_records r
JOIN books b ON r.book_id = b.id
WHERE r.borrowed_at >= CURRENT_TIMESTAMP - INTERVAL '90 days'
GROUP BY b.id, b.isbn, b.title, b.cover_url, b.available_copies
ORDER BY borrow_times DESC
LIMIT 10;
```

### 2.4 分类流通度与借阅偏好分析（Category Distribution）

* **计算口径**：按《中图法》一级大类统计全部借阅记录的分布比例。
$$\text{分类流通占比} = \frac{\text{某类目借阅次数}}{\text{全馆总借阅次数}} \times 100\%$$

---

### 2.5 违约与逾期风险精细化模型（Risk & Overdue Metrics）

1. **综合历史逾期率（Historical Overdue Rate）**：
   $$\text{逾期率} = \frac{\text{发生过逾期的借阅单总量}}{\text{历史归还借阅单总量}} \times 100\%$$
2. **损毁与遗失赔付统计**：
   * 汇总累计产生的破损单量、遗失单量、实缴赔偿金总额（`SUM(fine_amount)`）。

### 2.6 AI 导读效果评估与转化指标（AI Evaluation Metrics - Stage 0.5 新增）

基于 `ai_recommendation_logs` 表，系统提供以下真实、可度量的 AI 推荐效果指标，严禁制造虚假的“99%准确率”：

| 评估指标 | 业务定义与统计公式 | 数据采集来源 | 指标参考意义 |
| :--- | :--- | :--- | :--- |
| **推荐点击率 (CTR)** | $\text{CTR} = \frac{\text{推荐卡片点击进入图书详情次数}}{\text{AI 推荐生成总次数}} \times 100\%$ | 前端埋点事件 | 评估推荐书目是否激发读者好奇心与兴趣。 |
| **收藏转化率** | $\text{收藏率} = \frac{\text{推荐后 24 小时内加入收藏夹的书籍数}}{\text{推荐图书总数}} \times 100\%$ | `favorites` 关联 | 评估推荐内容是否与读者长期阅读意向相匹配。 |
| **借阅转化率** | $\text{转化率} = \frac{\text{推荐后 7 天内被成功借出的书籍数}}{\text{推荐图书总数}} \times 100\%$ | `borrow_records` 关联 | 评估 AI 推荐对线下实体图书流通的真实带动效果。 |
| **用户点赞好评率** | $\text{好评率} = \frac{\text{LIKE 反馈次数}}{\text{LIKE 次数} + \text{DISLIKE 次数}} \times 100\%$ | `ai_recommendation_logs.feedback` | 读者主观满意度直观反馈，用于调整 Prompt 策略。 |
