## 1. 统一借阅并发事务流程（自顶向下有序排他锁机制）

### 1.1 统一借阅事务时序与状态流转

为彻底解决锁粒度不统一与潜在死锁问题，借阅流通事务采用**自顶向下（先锁 Book，再锁 BookCopy）的确定性锁顺序**：

```mermaid
sequenceDiagram
    autonumber
    actor Reader as 读者 (Student)
    participant Controller as 借阅API控制器 (BorrowController)
    participant Service as 借阅流通服务 (BorrowEngineService)
    participant RuleEngine as 借阅规则服务 (RuleEngineService)
    participant DB as PostgreSQL 17 数据库

    Reader->>Controller: 发起借阅请求 (POST /api/v1/borrow-records) {bookId: 501, copyBarcode: "LIB-2026-000101"}
    Controller->>Service: 委派执行 borrowBook(userId, bookId, copyBarcode)
    Note over Service, DB: 开启强事务 @Transactional(isolation = Isolation.READ_COMMITTED)

    Service->>RuleEngine: 1. 业务资格校验 (在借量未超标、名下无逾期未还图书)
    RuleEngine->>DB: 检查 user_id 活跃借单与逾期记录
    alt 存在逾期未还图书 或 在借已达上限
        RuleEngine-->>Service: 校验不通过
        Service-->>Controller: 事务回滚，抛出 USER_HAS_OVERDUE_BOOKS 或 USER_BORROW_LIMIT_EXCEEDED
        Controller-->>Reader: 拦截并提示错误原因
    end

    Note over Service, DB: 【统一并发控制防线：Step 2 ~ Step 7】
    Service->>DB: 2. 锁定父级书目: SELECT * FROM books WHERE id = :bookId FOR UPDATE
    DB-->>Service: 获得 Book 行级排他锁 (串行化同一书目的借阅申请)

    Service->>Service: 3. 检查书目可用库存 (available_copies > 0，或当前读者持有该书有效的 READY 预约单)
    alt 库存 available_copies <= 0 且无有效 READY 预约单
        Service-->>Controller: 事务回滚，抛出 BOOK_NO_AVAILABLE_COPY
        Controller-->>Reader: 提示：“该书目前已全部借出，您可以提交缺书预约”
    end

    Service->>DB: 4. 定位目标在架副本: SELECT id FROM book_copies WHERE id = :copyId AND status = 'AVAILABLE'
    alt 副本不可用 (状态已被修改为 MAINTENANCE / DAMAGED 等)
        Service-->>Controller: 事务回滚，抛出 COPY_NOT_AVAILABLE
    end

    Service->>DB: 5. 锁定目标副本行: SELECT * FROM book_copies WHERE id = :copyId FOR UPDATE
    Service->>DB: 6. 更新物理副本状态: UPDATE book_copies SET status = 'BORROWED' WHERE id = :copyId
    Service->>DB: 7. 扣减书目可用库存: UPDATE books SET available_copies = available_copies - 1 WHERE id = :bookId
    Service->>DB: 8. 插入借阅记录表: INSERT INTO borrow_records(record_no, user_id, book_id, copy_id, status='BORROWING', due_at)
    alt 本次借阅消耗了 READY 预约单
        Service->>DB: 9. 同步更新预约单: UPDATE reservations SET status = 'COMPLETED', completed_at = now()
    end
    Service->>DB: 10. 写入借阅成功通知: INSERT INTO notifications(...)

    Note over Service, DB: 事务提交 COMMIT (释放 Book 与 Copy 行锁)
    Service-->>Controller: 返回借阅成功 VO
    Controller-->>Reader: 借阅成功 (201 Created)
```

### 1.2 统一有序锁机制的技术优势
1. **彻底消除死锁（Deadlock-Free）**：无论系统中存在多少个并发线程、借阅同一本书的不同副本，所有事务**一律先获取 `books` 表对应行的排他锁，再获取 `book_copies` 表对应行的排他锁**。加锁顺序完全一致，从图论拓扑上彻底杜绝循环等待导致的死锁。
2. **绝对防止库存超卖与负数**：在持有 `books` 行锁期间严格判定 `available_copies > 0` 并原子递减，同时底层有数据库约束 `CHECK (available_copies >= 0)` 双重兜底，高并发下绝不穿透。

## 2. 图书归还与预约队列就绪激活流程

### 2.1 归还流通时序图

```mermaid
sequenceDiagram
    autonumber
    actor Reader as 读者 / 柜台管理员
    participant Service as 归还核心服务 (ReturnEngineService)
    participant ResvService as 预约调度引擎 (ReservationService)
    participant DB as PostgreSQL 17 数据库

    Reader->>Service: 提交归还请求 (POST /api/v1/borrow-records/{id}/return)
    Note over Service, DB: 开启数据库事务 @Transactional

    Service->>DB: 1. 锁定借阅记录与关联副本: SELECT * FROM borrow_records WHERE id = :id FOR UPDATE
    Service->>Service: 2. 校验状态 (BORROWING 或 OVERDUE) 并计算是否逾期违约
    alt 超过截止时间 (now > due_at)
        Service->>DB: 更新借单: status = 'OVERDUE_RETURNED', returned_at = now(), fine_amount = ...
    else 按期归还
        Service->>DB: 更新借单: status = 'RETURNED', returned_at = now()
    end

    Service->>DB: 3. 恢复物理副本状态: UPDATE book_copies SET status = 'AVAILABLE' WHERE id = :copyId
    Service->>DB: 4. 锁定父级书目: SELECT * FROM books WHERE id = :bookId FOR UPDATE

    Service->>ResvService: 5. 检索该书是否存在排队中的预约 (checkWaitingReservation)
    ResvService->>DB: SELECT * FROM reservations WHERE book_id = :bookId AND status = 'WAITING' ORDER BY queue_number ASC LIMIT 1 FOR UPDATE

    alt 存在等待预约者 (命中读者 B)
        ResvService->>DB: 5.1 激活读者 B 预约单: status = 'READY', expired_at = now() + 48小时, copy_id = :copyId
        ResvService->>DB: 5.2 触发就绪站内信通知读者 B
        Note over ResvService: 注意：书目可用库存 available_copies 保持不加 (该名额已指派锁定给读者B)
    else 无任何等待预约者
        Service->>DB: 5.3 正常增加书目可用在架库存: UPDATE books SET available_copies = available_copies + 1 WHERE id = :bookId
    end

    Note over Service, DB: 事务提交 COMMIT
    Service-->>Reader: 归还成功响应 (200 OK)
```

## 3. 图书合规续借流程设计

```mermaid
flowchart TD
    Start["读者发起续借请求 (POST /borrow-records/{id}/renew)"] --> Lock["锁定当前借阅单行记录 (FOR UPDATE)"]
    Lock --> CheckStatus{"借阅单状态是否为 BORROWING?"}
    CheckStatus -- 否 (已逾期或已归还) --> Reject1["拒绝: 当前记录状态不允许续借 (400)"]
    CheckStatus -- 是 --> CheckOverdue{"当前读者是否有名下任何其他逾期书籍?"}

    CheckOverdue -- 存在逾期未还 --> Reject2["拒绝: 存在逾期未还图书，借阅权限已冻结 (403)"]
    CheckOverdue -- 无逾期 --> CheckRenewCount{"已续借次数 < 规则配置上限(max_renew_count)?"}

    CheckRenewCount -- 已达上限 --> Reject3["拒绝: 已达到最大允许续借次数 (400)"]
    CheckRenewCount -- 未达上限 --> CheckReservation{"该书目是否存在 WAITING 预约者?"}

    CheckReservation -- 存在预约等待 --> Reject4["拒绝: 该书已有其他读者预约排队，不允许续借 (409)"]
    CheckReservation -- 无人预约 --> Success["允许续借: \n1. 更新 due_at = due_at + renew_duration_days\n2. renew_count = renew_count + 1\n3. 记录日志并下发通知"]
    Success --> End["返回最新还书截止日期 (200 OK)"]
```

## 4. 预约超时释放巡检调度流程（Cron Job）

```mermaid
flowchart TD
    CronTrigger["定时巡检调度器触发 (每 10 分钟执行一次)"] --> QueryExpired["检索逾期未取的预约单: \nWHERE status = 'READY' AND expired_at < now()"]
    QueryExpired --> Loop{"是否存在超期记录?"}
    Loop -- 否 --> Finished["巡检结束，休眠"]
    Loop -- 是 --> FetchOne["加锁锁定预约单与关联书目 (FOR UPDATE)"]
    FetchOne --> MarkExpired["1. 将当前预约单标记为 status = 'EXPIRED'"]
    MarkExpired --> SendNotice["2. 发送站内信通知该读者: '预约已超时失效'"]
    SendNotice --> CheckNext{"该书目是否还有下一位 WAITING 预约者?"}

    CheckNext -- 存在下一位读者 C --> AssignNext["顺延指派给读者 C: \n1. 绑定 copy_id\n2. 读者 C status = 'READY'\n3. 设置读者 C expired_at = now() + 48h\n4. 发送取书提醒给读者 C"]
    CheckNext -- 无后续等待者 --> ReleaseShelf["释放回公共在架可用: \nUPDATE books SET available_copies = available_copies + 1 WHERE id = :bookId"]
    AssignNext --> Loop
    ReleaseShelf --> Loop
```

## 5. Excel 图书批量导入业务流程（Stage 0.5 新增）

```mermaid
sequenceDiagram
    autonumber
    actor Librarian as 图书管理员
    participant Controller as 导入控制器 (BookImportController)
    participant Service as 批量导入服务 (BookImportService)
    participant Validator as 四层数据校验器
    participant DB as PostgreSQL 17 数据库

    Librarian->>Controller: 上传 Excel 文件 (POST /api/v1/books/import/upload-preview)
    Controller->>Service: 解析文件流 (Apache POI)
    Service->>Validator: 执行行数据清洗与四层校验
    Note over Validator: 1. 必填字段非空校验<br/>2. 价格与ISBN格式校验<br/>3. Excel 内部条码查重<br/>4. 数据库已有条码与分类代码校验
    Validator-->>Service: 返回校验统计结果 (合格列表、警告提示、失败原因明细)
    Service-->>Controller: 组装预览结果 VO
    Controller-->>Librarian: 前端弹窗展示导入预览 (展示成功条数与错误行列表)

    Librarian->>Controller: 确认无误，提交落库 (POST /api/v1/books/import/confirm) {importToken: "..."}
    Controller->>Service: 执行事务批量落库 @Transactional
    Note over Service, DB: 开启批量写入大事务
    loop 遍历每一条合法数据
        alt ISBN 在 books 表已存在
            Service->>DB: 原书目追加 BookCopy，total_copies++，available_copies++
        else ISBN 属于新书
            Service->>DB: 插入 books 新书目记录
            Service->>DB: 插入 book_authors 作者关联
            Service->>DB: 插入 book_copies 物理单册记录
        end
    end
    Note over Service, DB: 事务提交 COMMIT
    Service-->>Controller: 导入成功 (返回实际入库总书目数与总副本数)
    Controller-->>Librarian: 提示：“批量导入成功，共入库 50 种书目，150 册副本”
```

## 6. 异常流转：挂失与损坏责任认定流程

1. **读者线上申报挂失**：借单状态变更为 `ABNORMAL_LOST`，冻结逾期天数累加。
2. **管理员核验定损**：系统依据图书标价与规则赔付倍数（如原价 1.5 倍）生成定损单。
3. **清缴赔偿与结案**：
   * 读者结清赔偿款后，管理员执行结案：借阅单归档，解除读者借阅冻结；
   * 物理副本变更为 `LOST` 或 `SCRAPPED`，书目总藏书量 `total_copies` 减 1。
